# codex-barbar 额度准确性、紧凑状态面与透明度设计

日期：2026-08-14
状态：待用户审核
适用产品：Windows `codex-barbar` Tauri 桌面应用

## 1. 背景与问题

当前安装版存在四组相互关联的问题：

1. 状态面显示的额度与当前 Codex 不一致。用户截图中 codex-barbar 显示每周剩余 100%，最后更新时间仍停留在 2026-08-09；当前 Codex 界面显示每周剩余 98%，2026-08-20 重置。
2. 任务栏胶囊固定为约 318px 宽，并在内容区使用可扩张列，导致关闭按钮前出现大段空白；这段空白同时占用任务栏点击区域。
3. 任务栏与悬浮球背景过深，字号、行高和间距偏大，设置窗口也存在横向标签拥挤、字段松散和大面积空白。
4. 额度状态颜色没有统一按“剩余额度”表达，高、中、低状态无法一眼识别。

本轮同时修复数据准确性和呈现层。状态面不能用漂亮的 UI 掩盖过期或虚构的数据。

## 2. 已确认根因

### 2.1 额度未刷新

本机数据库 `%LOCALAPPDATA%\codex-barbar\data\codex-barbar.db` 中仅有一条 2026-08-09 的缓存快照：

- 窗口时长：10080 分钟（每周）
- 剩余额度：100%
- 最近刷新错误：`CODEX_NOT_FOUND`

当前 `codex` 命令由 OpenCodex 自定义 `codex.cmd` 包装器接管。codex-barbar 的安全解析器只允许官方 npm shim 或原生 `codex.exe`，因此正确拒绝执行该自定义脚本。但官方 `@openai/codex` 0.146.0 npm 包及其中的 Windows 原生 `codex.exe` 仍然存在。

因此根因不是百分比计算错误，而是安全发现流程未能从被包装的入口继续定位官方 npm 包内的原生 Codex 程序，导致刷新失败后持续显示旧缓存。

### 2.2 固定额度窗口假设错误

当前状态面视图模型固定查找 300 分钟和 10080 分钟两个窗口，并将它们命名为“5H”和“周”。用户当前的 Codex 只返回每周额度；UI 不应构造不存在的 5 小时额度，也不应为空缺窗口保留位置。

## 3. 目标

- 从可信的官方 Codex 原生程序实时读取当前账户额度，同时不修改、不停用 OpenCodex。
- 后端返回多少个额度窗口，状态面就显示多少个；当前只有每周额度时只显示每周额度。
- 任务栏胶囊按实际内容收缩，删除关闭按钮前的弹性空白。
- 用户名在任务栏状态面只显示前 6 个可见字符；完整身份保留在悬浮提示和主面板。
- 任务栏与悬浮球分别支持 0–80% 背景透明度，默认均为 20%。
- 按剩余额度平均三等分使用绿色、黄色、红色；过期、错误和刷新中状态使用灰色。
- 把设置窗口改为紧凑、清晰、中文化的 macOS 风格布局。

## 4. 非目标

- 不执行或信任 OpenCodex 自定义包装脚本。
- 不修改、删除或禁用 OpenCodex。
- 不改变 Codex 登录状态、账户或凭据。
- 不从网页抓取额度，不调用未授权的私有接口。
- 不新增第三方依赖、DLL 注入或任务栏 Explorer 进程注入。
- 不在本轮增加用户自定义颜色阈值；阈值保持固定、统一且可测试。
- 不重做托盘主面板的完整信息架构；只保证其额度与状态面使用同一真实数据。

## 5. 方案选择

### 5.1 Codex 发现方案

采用“自动安全定位官方原生程序 + 手动覆盖兜底”：

1. 继续按现有顺序检查用户显式覆盖、PATH 和已知原生安装位置。
2. 如果 PATH 中的 `codex.cmd` 不是官方 shim，不执行它。
3. 从该入口所在的 npm 前缀检查官方包结构：
   `node_modules\@openai\codex\package.json`、平台包 `@openai\codex-win32-x64` 以及其 vendor 目录中的 `codex.exe`。
4. 只有当所有路径均为普通文件、不是重解析点、规范化后仍位于预期 npm 包树内，并且包名、平台和版本结构一致时，才接受原生 `codex.exe`。
5. 对接受的原生程序执行现有版本探测和 App Server 握手；任一步失败都返回稳定错误，不回退执行自定义脚本。
6. 设置页继续保留“Codex 可执行文件路径”作为人工恢复入口。

该方案不改变用户平时从终端运行 `codex` 的行为，只影响 codex-barbar 自己的只读账户和额度刷新进程。

### 5.2 状态面布局方案

采用用户选择的 B 方案：单行紧凑胶囊。

当前只有每周额度时，视觉顺序为：

`Codex 图标 | 用户名前 6 位 | 周 98% | 8/20 | ×`

所有列均为内容宽度，不使用 `1fr`、`flex-grow` 或其他弹性占位。关闭按钮紧贴最后一个信息项。当前示例宽度约 168px，高度 40px；实际宽度由内容测量得出，而不是固定 318px。

## 6. 数据与刷新设计

### 6.1 单一数据来源

额度仍来自官方 Codex App Server 的 `account/rateLimits/read`。Rust 负责：

- 解析 `usedPercent`、窗口时长、重置时间和 limit id；
- 规范化百分比至 0–100；
- 计算 `remainingPercent`；
- 持久化最后一次成功快照；
- 将刷新错误、数据新鲜度和协议异常通过现有 DTO 传给前端。

React 不重新计算协议字段，不用页面数据覆盖 Rust 结果。

### 6.2 动态额度窗口

状态面视图模型不再固定要求 300 分钟和 10080 分钟。它按以下顺序生成展示窗口：

1. `primary`
2. `secondary`
3. `additionalWindows`

对重复的 limit id 或完全相同的窗口做稳定去重。每个窗口的标签优先使用已知时长的本地化名称；未知窗口使用后端标签，仍未知时使用简短的“额度”。

当前只有 10080 分钟窗口时只生成“周”一项。只有后端真实返回 300 分钟窗口时才显示“5 小时”或“5H”。

### 6.3 最紧迫窗口

悬浮球折叠态只能展示一个值。选择规则为：

- 在所有真实额度窗口中选择 `remainingPercent` 最低者；
- 相同剩余额度时保持后端稳定顺序；
- 不按当前显示模式反转紧迫性。

任务栏单行在空间允许时依次显示所有真实窗口；超出 Windows 任务栏安全宽度时保留最紧迫窗口，其余信息进入悬浮提示和展开态。

### 6.4 缓存和错误呈现

刷新失败时保留最后一次成功快照，但必须同时满足：

- 颜色改为灰色，不显示绿、黄、红健康状态；
- 文案或悬浮提示明确显示“缓存”及最后更新时间；
- 主面板继续显示具体错误与恢复动作；
- 不把旧缓存标成“已更新”或“正常”；
- 没有成功快照时显示“额度不可用”，不显示 0% 或 100%。

刷新中也使用灰色和轻量动画，直到取得新的成功快照后再恢复额度颜色。

## 7. 额度颜色模型

颜色始终基于剩余额度，不受“显示剩余 / 显示已用”偏好影响：

| 剩余额度 | 状态 | 颜色 |
|---|---|---|
| 67–100% | 高 | 绿色 |
| 34–66% | 中 | 黄色 |
| 0–33% | 低 | 红色 |
| 刷新中、缓存过期、错误、缺失 | 未确认 | 灰色 |

边界值包含在表中所列区间。颜色应用于任务栏百分比、悬浮球圆环、展开态进度条和必要的状态文字；账户名、重置日期和关闭按钮保持中性色，避免整块染色。

颜色不是唯一信号：悬浮提示和可访问名称同时包含“高 / 中 / 低 / 缓存 / 不可用”。

## 8. 任务栏状态面

### 8.1 内容

- 图标或简短头像。
- `compactIdentity`：清理后的账户显示名或邮箱的前 6 个 Unicode 字符；不足 6 个则原样显示。
- 每个真实额度窗口的短标签、当前显示百分比和最近重置日期。
- 关闭按钮。

完整账户名、完整重置倒计时、所有额度窗口、显示模式和数据状态放入 `title` 与可访问名称。

### 8.2 尺寸与原生窗口

- 高度：40px。
- CSS 不使用弹性空白列。
- React 在内容或设置变化后测量胶囊的实际 CSS 像素宽度，并通过受限 Tauri 命令请求调整原生窗口宽度。
- Rust 对宽度做固定安全范围钳制，并继续保证窗口落在任务栏矩形内。
- 关闭按钮始终可见且可点击，失败时显示原位错误并允许重试。
- Explorer 重启、DPI、缩放和任务栏位置变化后重新测量、定位。

### 8.3 透明度

`taskbarStatusOpacity` 表示背景不透明度百分比，范围 0–80，默认 20。

- 0：背景和装饰边框完全透明；文字描边、额度颜色、焦点框和关闭按钮仍可见。
- 1–80：将数值转换为背景 alpha；轻微模糊、阴影和边框强度按同一比例受限变化。
- 不改变整个窗口或文字 opacity，避免内容也变淡。

## 9. 悬浮球

### 9.1 折叠态

- 显示最紧迫的真实额度窗口。
- 显示短周期标签和当前显示百分比。
- 圆环颜色遵循统一剩余额度阈值。
- 没有额度或数据不可信时显示中性占位与灰色圆环。

### 9.2 展开态

- 只为真实存在的额度窗口生成行，不保留“5 小时”和“每周”的固定空卡位。
- 每行显示周期、百分比和重置时间。
- 账户名在展开态可显示完整值；折叠态不显示长账户名。
- 现有悬停展开、拖拽、点击打开主面板、Escape 收起和关闭行为保持不变。

### 9.3 透明度

`floatBallOpacity` 独立于任务栏，范围 0–80，默认 20。只影响折叠球和展开卡片的背景、边框、模糊与阴影，不影响文本、圆环或交互状态。

## 10. 设置模型与持久化

在现有 `AppSettings`、Rust bridge DTO 和 TypeScript DTO 中增加：

- `taskbarStatusOpacity: number`
- `floatBallOpacity: number`

规范：

- 持久化值为整数百分比；合法范围 0–80。
- 缺失字段迁移为 20，保持旧设置兼容。
- 越界输入由 Rust 钳制或拒绝，前端不能成为唯一校验层。
- 更新后通过现有 `codexbar:settings-updated` 事件同步所有窗口。
- 开关关闭状态面时保留其透明度设置。
- 不改变现有 `taskbarStatusEnabled`、`floatBallEnabled`、位置保存或展开状态语义。

## 11. 紧凑 macOS 风格设置窗口

### 11.1 布局

- 目标窗口约 680×500，保留无原生装饰的深色外观和明确关闭入口。
- 左侧为窄侧栏，容纳现有 8 个分类：通用、账户、通知、菜单栏、菜单、用量与费用、高级、关于。
- 右侧为当前分类内容区；不再使用顶部横向 8 个按钮。
- 未实现分类显示紧凑说明，不用空白区域假装内容。

### 11.2 密度与语言

- 正文字号 12–14px，标题按层级小幅放大。
- 输入控件、选择框和按钮目标高度约 30px。
- 字段纵向间距 10–12px，设置卡内边距 12–14px。
- 当前用户选择简体中文时，设置页标签、字段、选项和状态文案全部使用中文；英文仍由现有语言偏好支持。
- 保留 Tab、方向键、空格、Enter、Escape 和可见焦点样式。

### 11.3 状态面设置卡

通用页包含两张紧凑卡：

1. 任务栏状态：启用开关、透明度滑块、当前百分比值。
2. 悬浮球：启用开关、透明度滑块、当前百分比值。

透明度滑块范围 0–80，键盘步进 1，视觉刻度可使用 0、20、40、60、80。即使状态面暂时关闭，滑块仍可编辑，以便下次开启直接采用保存值。

## 12. 安全与隐私

- 永不执行未知 `.cmd`、`.ps1`、`.bat` 或 shell 包装器。
- 官方 npm 原生程序发现必须防止目录穿越、重解析点和规范化后逃逸。
- 不记录原始凭据、token、cookie、完整协议响应或环境秘密。
- 诊断仅记录安装类别、版本、稳定错误码、窗口种类和刷新时间。
- 状态面默认只显示账户名前 6 位；完整账户名只在用户主动打开或悬停的本地 UI 中出现。

## 13. 错误处理

- 官方 npm 原生程序发现失败：保持 `CODEX_NOT_FOUND` 或更具体的稳定、非敏感发现错误；主面板提供手动路径入口。
- App Server 版本或握手失败：显示不兼容错误，不执行包装器兜底。
- 透明度更新持久化失败：恢复原设置值并显示可重试错误。
- 原生任务栏宽度调整失败：保留当前安全宽度，不销毁窗口；下一次内容、DPI 或任务栏事件重试。
- 辅助窗口关闭失败：恢复启用状态并允许再次点击关闭。

## 14. 测试与验证

### 14.1 Rust

- 非官方包装器旁存在合法官方 npm 平台包时，解析到包内原生 `codex.exe`。
- 包名、平台、版本、目录边界、文件类型或重解析点不合法时拒绝。
- 未知包装器永不执行。
- 官方原生程序仍通过现有版本和 App Server 能力探测。
- 新透明度字段缺失时迁移为 20，边界 0 和 80 保留，越界被规范化。
- 任务栏动态宽度请求在安全范围内钳制。

### 14.2 React / TypeScript

- 只有每周窗口时不渲染“5H”，显示周额度和重置日。
- 后端真实返回多个窗口时按稳定顺序渲染，并正确选择最紧迫窗口。
- 账户显示名按 Unicode 字符截取前 6 位，完整值仍在可访问名称中。
- 67、66、34、33 四个边界颜色准确。
- 刷新中、stale、错误和 missing 始终为灰色。
- 任务栏 DOM 不含弹性占位列，关闭按钮紧随内容。
- 两个透明度滑块独立更新各自字段，并响应跨窗口设置事件。
- 设置侧栏可用键盘切换，中文文案和焦点状态可见。

### 14.3 Windows 原生验证

新构建必须在真实 Windows 桌面上验证：

1. 关闭旧的单实例进程，构建并启动最新桌面程序。
2. 在保留 OpenCodex 包装器的环境下，确认 codex-barbar 发现官方包内原生 Codex，不修改终端 `codex` 行为。
3. 手动刷新后对照 Codex 当前用量页，确认每周百分比和重置日一致。
4. 确认当前只有周额度时任务栏和悬浮球均不显示 5H。
5. 测试 0%、20%、80% 两组独立透明度；确认文字、圆环、焦点和关闭仍可见。
6. 检查任务栏胶囊实际宽度约为内容宽度，关闭按钮前不存在可点击空白。
7. 检查不同 DPI、任务栏位置、Explorer 重启、拖拽和单实例重启。
8. 使用 CUA 驱动截图和交互；如果 CUA 仍不可用，使用 Win32/UIA 等效证据并明确记录限制。

### 14.4 完整门禁

运行仓库本地 CI 切片，至少覆盖 Rust、Tauri、Frontend、Format 和 Clippy；重新构建 NSIS 安装器并在当前用户范围完成覆盖安装验证。

## 15. 验收标准

- 当前机器在不移除 OpenCodex 的情况下成功刷新官方 Codex 实时额度。
- Codex 显示每周剩余 98%、8 月 20 日重置时，codex-barbar 对应状态面显示相同含义和数值。
- 没有真实 5 小时窗口时，任何状态面都不出现 5H。
- 任务栏 B 方案显示前 6 位用户名，关闭按钮紧贴内容，内部无大块空白。
- 任务栏和悬浮球透明度可独立设为 0–80%，默认 20%，重启后保持。
- 67–100% 绿、34–66% 黄、0–33% 红；不可信数据灰色。
- 设置页采用左侧分类、右侧内容的紧凑中文布局，状态面设置可直接操作。
- 所有自动测试、构建和 Windows UI 验证通过，并产出最新可安装 NSIS 包。
